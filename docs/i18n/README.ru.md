# AetherUpload-Webman

Этот проект — порт популярного расширения для загрузки больших файлов в Laravel [AetherUpload-Laravel](https://github.com/peinhu/AetherUpload-Laravel); для модели долгоживущих процессов [webman](https://www.workerman.net/webman) заново написаны чтение конфигурации, работа с конкурентностью и слой хранения.

**Что он решает**

При загрузке больших файлов напрямую из браузера не обойтись без трёх проблем: файл больше `post_max_size` — загрузка не пройдёт; пропала сеть — начинай заново; один и тот же файл передаётся повторно. AetherUpload решает это так: файл нарезается в браузере на фрагменты, которые по одному дописываются в один временный файл на сервере, а при записи на диск получают имя из md5 своего содержимого. В итоге **загрузка, возобновление после обрыва, мгновенная загрузка, дедупликация и проверка целостности** работают на одном и том же механизме, весь файл при этом никогда не читается в память и не нужна таблица в базе данных, где хранилось бы, «где лежит файл».

**Его форма**

Один composer-пакет, **ядро не связано с фреймворком-хостом**: один и тот же код работает под webman, Laravel, ThinkPHP, Symfony, Slim, Hyperf и Yii2 (см. [Поддерживаемые фреймворки](#поддерживаемые-фреймворки)). Конфигурацию, маршруты, консольные команды, языковые файлы и фронтенд-скрипты для хоста раскладывают команды установки / публикации; база данных не нужна; Redis требуется только при включённой мгновенной загрузке и является опциональной зависимостью.

> Единственное исключение — `Install.php`: установочный скрипт, запускаемый по `composer require`, работает до старта приложения-хоста, когда `Runtime` ещё не привязан; в этой ситуации он привязывает адаптер webman сам и откатывается к внутрипакетному `config/app.php`.

> До установки всё это файлы внутри пакета; после `composer require` скрипт `Install.php` по соответствиям из таблицы выше раскладывает конфигурацию, команды, фронтенд-скрипты и языковые файлы в нужные места приложения-хоста.

# Архитектура

<img src="img/aetherupload-architecture.ru.svg" alt="Схема архитектуры AetherUpload-Webman">

- **Клиент**: достаточно подключить один `aetherupload-all.js` (внутри zepto и spark-md5); он считает md5, нарезает файл, показывает прогресс и сам повторяет попытку после обрыва.
- **Сервер**: у `UploadController` всего две точки входа (предобработка и запись фрагмента); `PartialResource` отвечает за путь, дозапись и переименование, `Header` хранит только chunkIndex; конфигурация снимается `ConfigMapper` на каждый запрос, чтобы в долгоживущем процессе параллельные запросы не путали группы.
- **Хранение и эксплуатация**: на диске всегда только три вида файлов — фрагменты `*.part`, точки возобновления в `_header/`, готовые файлы `<md5>.<ext>`; Redis используется только при включённой мгновенной загрузке; при включённом `x_accel_redirect` файл отдаёт nginx напрямую, попутно закрывая Range и докачку.

# Логика проектирования

<img src="img/aetherupload-design.ru.svg" alt="Логика проектирования AetherUpload-Webman">

Помимо трёх решений со схемы есть и отдельный выбор: **индекс мгновенной загрузки сделан опциональной зависимостью, а у каждой записи свой TTL**. Сайт без Redis по-прежнему загружает файлы (просто мгновенная загрузка не работает); на сайте с Redis каждая запись истекает сама через `SETEX` — сроки жизни не общие, и индекс не разрастается бесконечно при непрерывных загрузках; после обновления старые записи по прежним hash всё ещё читаются. За согласованность отвечают `aetherupload:build` (ежедневная перестройка) и `aetherupload:clean` (сбор временных файлов по mtime).

# Жизненный цикл загрузки

<img src="img/aetherupload-lifecycle.ru.svg" alt="Жизненный цикл загрузки AetherUpload-Webman">

Основной путь состоит всего из четырёх шагов: **предобработка → фрагменты (цикл) → проверка последнего фрагмента → запись на диск**. Предобработка создаёт пустой `.part` и записывает в header `chunkIndex=0`; порядок для каждого фрагмента неизменен: «проверка → дозапись → запись chunkIndex обратно»; только для последнего фрагмента проверяются размер и MIME, пересчитывается md5 всего файла, файл переименовывается в `<md5>.<ext>` и попадает в индекс мгновенной загрузки.

Отдельного пояснения заслуживают два обходных пути:

- **Попадание в мгновенную загрузку**: на этапе предобработки обнаруживается готовый файл с тем же md5, сразу возвращается его путь — передавать не нужно ни одного фрагмента.
- **Обрыв и восстановление**: повторная отправка того же номера идемпотентно пропускается; скачок номера или обрезанный фрагмент возвращают только ошибку и **не чистят** `.part` и header, поэтому в слабой сети клиент может повторять попытки, пока не догрузит недостающий фрагмент. По-настоящему чистят только два случая — непройденная проверка последнего фрагмента (отбрасывается весь файл) и `aetherupload:clean` по cron после закрытия страницы, собирающий мусор по mtime.

# Возможности
- [x] прогресс в процентах  
- [x] ограничение по типу файла  
- [x] ограничение по размеру файла  
- [x] поддержка нескольких языков  
- [x] конфигурация групп ресурсов  
- [x] событие завершения загрузки   
- [x] синхронная загрузка *①*  
- [x] возобновление после обрыва связи *②*  
- [x] мгновенная загрузка файла *③*  
- [x] свой middleware *④*  
- [x] свои маршруты   
- [x] мягкий режим

*①: по сравнению с асинхронной загрузкой синхронная чуть медленнее при достаточной полосе, зато склейка файла идёт одновременно с загрузкой; при асинхронной порядок завершения фрагментов не определён, поэтому склеить их можно только после того, как готовы все фрагменты, и ближе к концу загрузки приходится долго ждать. В синхронном режиме в каждый момент передаётся только один фрагмент, за единицу времени расходуется меньше памяти сервера, и по сравнению с асинхронным режимом одновременно могут загружать больше людей.*  

*②: возобновление после обрыва связи — не то же самое, что докачка с точки останова: под обрывом связи понимается ситуация, когда при пропадании сети или нестабильном беспроводном соединении, пока страница не закрыта, компонент загрузки периодически повторяет попытку сам, и как только сеть вернётся, файл продолжит загружаться с того фрагмента, который не удалось передать. После обновления или повторного открытия закрытой страницы возобновить загрузку нельзя — переданная ранее часть становится недействительным файлом.*  

*③: для мгновенной загрузки нужны Redis на сервере и поддержка в браузере (FileReader, File.slice()) — без любого из двух она не работает. По умолчанию выключена, включается в конфигурации.*  

*④: вместе со своим middleware можно управлять правами на доступ к загруженным ресурсам и на их скачивание.*


# Поддерживаемые фреймворки

Ядро (фрагменты, возобновление, мгновенная загрузка, проверки, адресация) не связано с фреймворком-хостом; один и тот же пакет работает под перечисленными ниже фреймворками, и каждый прикрыт сквозным тестом, который **по-настоящему ставит фреймворк и по-настоящему проходит весь путь загрузки**:

| Фреймворк | Способ подключения | Сквозной тест |
|---|---|---|
| webman | нативная поддержка (`composer require` сразу раскладывает конфигурацию/маршруты/команды/фронтенд-скрипты) | `tests/Integration/webman/` |
| Laravel | ServiceProvider + `vendor:publish` | `tests/Integration/laravel/` |
| ThinkPHP | регистрация Service в `app/service.php` | `tests/Integration/thinkphp/` |
| Symfony | Bundle + импорт ресурса маршрутов | `tests/Integration/symfony/` |
| Slim | одна строка `Bootstrap::create()` | `tests/Integration/slim/` |
| Hyperf | `ConfigProvider` | `tests/Integration/hyperf/` |
| Yii2 | Bootstrap в `bootstrap` приложения | `tests/Integration/yii/` |

> `webman` в имени пакета — дань истории (изначально плагин поддерживал только webman); на работу с остальными фреймворками это не влияет.

## Два общих шага

Независимо от фреймворка после установки пакета есть два **обязательных** действия (в webman их выполняет установочный скрипт сам, в остальных фреймворках соответствующие команды запускаются вручную):

1. **Создать каталоги хранилища**: `aetherupload:groups` — создаёт `root_dir`, `_header` и каталоги групп.
   **Без этого работа точно сломается**: `createGroupSubDir()` в ядре — это нерекурсивный `mkdir`, при отсутствии родительского каталога он сразу возвращает false, а ошибка единообразно превращается в общее `upload_error`, и при разборе трудно догадаться, что дело в каталоге.
2. **Опубликовать файлы**: `aetherupload:publish` (в Laravel — `vendor:publish --tag=aetherupload-*`) — раскладывает языковые файлы и фронтенд `js` туда, откуда хост может их отдать.

> Разделитель в именах команд следует консольным соглашениям каждого фреймворка: webman / Laravel / ThinkPHP / Symfony / Hyperf / Slim используют `:`, **Yii — `/`** (`php yii aetherupload/groups`). Примеры для каждой из них ниже можно копировать и запускать как есть.

## Подключение по фреймворкам

**Laravel**

```php
// bootstrap/providers.php (Laravel 11+) или массив providers в config/app.php
AetherUpload\Adapter\Laravel\AetherUploadServiceProvider::class,
```
```bash
php artisan vendor:publish --tag=aetherupload-config         # публикует config/aetherupload.php
php artisan vendor:publish --tag=aetherupload-translations   # публикует языковые файлы
php artisan vendor:publish --tag=aetherupload-assets         # публикует фронтенд js
php artisan aetherupload:groups
```
> В composer.json этого пакета **нет** `extra.laravel.providers` (зависимости шести фреймворков взаимоисключающие, автоматическое обнаружение жёстко прописать нельзя), поэтому provider регистрируется вручную.
> Слияние конфигурации — **поверхностное**: как только приложение опубликует `config/aetherupload.php`, его `groups` **целиком заменят** значения по умолчанию из плагина — добавляя группу, перенесите в файл и группы по умолчанию.

**ThinkPHP**

```php
// app/service.php
return [ \AetherUpload\Adapter\ThinkPhp\AetherUploadService::class ];
```
```bash
php think aetherupload:groups
php think aetherupload:publish
```
> Здесь тоже помните, что `groups` заменяются целиком; кроме того, `config/route.php` и `config/lang.php` — **обязательные файлы**: без них фреймворк получит null в `array_merge`/`array_change_key_case` и бросит TypeError.

**Symfony**

```php
// config/bundles.php
AetherUpload\Adapter\Symfony\AetherUploadBundle::class => ['all' => true],
```
```yaml
# config/routes.yaml (маршруты бандла в Symfony обязательно импортируются со стороны приложения — автозагрузки нет)
aetherupload:
    resource: '@AetherUploadBundle/Resources/config/routes.php'
    type: php
```
> Дерево `Configuration` объявляет все ключи конфигурации; незадекларированный ключ уронит запуск контейнера (а не будет молча проигнорирован).

**Slim**

```php
// public/index.php
$app = \AetherUpload\Adapter\Slim\Bootstrap::create([
    'config'    => require __DIR__ . '/../config/aetherupload.php',   // если опустить — берутся значения по умолчанию из пакета
    'base_path' => dirname(__DIR__),
    'redis'     => static fn () => new Predis\Client(['database' => 0]),   // нужен для мгновенной загрузки
]);
$app->run();
```
> Ответы PSR-7 в Slim неизменяемы, поэтому результат работы ядра превращается в настоящий PSR-7 на слое `Bootstrap::handler()` (**единственная точка преобразования**; в middleware это не пройдёт).
> В Slim нет консольных соглашений, поэтому пакет даёт готовые классы входа для четырёх команд, а сам скрипт входа нужно положить самостоятельно (четыре строки):
> ```php

# Использование  
**Загрузка файла**  

Смотрите файл-пример и комментарии в нём: подключайте нужные файлы и код на страницах, где требуется загрузка больших файлов.

**Настройка групп**  

Добавьте новую группу в `groups` в конфигурации плагина и выполните `php webman aetherupload:groups` — нужные каталоги создадутся автоматически.  
```php
'video' => [
    'group_dir'                    => 'video',
    'resource_maxsize'             => 0,
    'resource_extensions'          => [],
    'event_before_upload_complete' => false, 
    'event_upload_complete'        => false,
],
```
На фронтенде группа загрузки задаётся вызовом метода `setGroup('имя группы')`; учтите, что группа должна уже существовать и что **имя не может содержать подчёркиваний** (оно участвует в кодировании пути хранения: с подчёркиванием ресурсы этой группы не удастся найти, и всё сломается уже на этапе конфигурации и загрузки).

**Включение мгновенной загрузки (нужны Redis и поддержка в браузере)**  

Смотрите раздел про Redis в документации Webman и поставьте нужные зависимости.  
Установите Redis и запустите сервис.  
Поставьте пакет predis: `composer require predis/predis`.  
В `config/redis.php` задайте для `client` значение `predis`.  
В конфигурации плагина выставьте `instant_completion` в `true`.

*Подсказка: в Redis хранится список мгновенной загрузки, соответствующий реальным файлам ресурсов; любые изменения реальных файлов — добавление и удаление — нужно синхронизировать с этим списком, иначе появятся грязные данные.  
Добавление расширение берёт на себя; когда же требуется удалить файл ресурса, пользователь должен сам вызвать соответствующие методы — они удаляют и файл, и запись в списке мгновенной загрузки.* 
```php
\AetherUpload\Util::deleteResource($savedPath); //удаляет соответствующий файл ресурса
\AetherUpload\Util::deleteRedisSavedPath($savedPath); //удаляет соответствующую запись мгновенной загрузки в Redis
``` 
*Обе операции идемпотентны: если файла или записи уже нет, они всё равно вернут true.* 

**Свой middleware**  

Смотрите раздел про middleware маршрутов в документации Webman: создайте свой middleware и впишите его имя в соответствующее место конфигурации.  
```php
'middleware_download' => [app\middleware\MiddlewareA::class,app\middleware\MiddlewareB::class],
```  
С его помощью можно управлять правами на загрузку, доступ и скачивание файлов.

**Свои маршруты**  

В конфигурации плагина правьте такие опции, как `'route_uploading' => '/aetherupload/uploading'`, а на фронтенде вызывайте соответствующие методы, например `setUploadingRoute('/aetherupload/uploading')`.  
Маршруты доступа к файлам и скачивания после правки работают сразу, вызывать методы фронтенда для них не нужно.
 
**События завершения загрузки**  

События делятся на «до завершения загрузки» и «после завершения загрузки»; смотрите раздел про Event из часто используемых компонентов в документации Webman.  
В `config/event.php` назначьте соответствующие классы-обработчики для `aetherupload.before_upload_complete` и `aetherupload.upload_complete`.  
В конфигурации плагина выставьте соответствующие опции внутри `groups` в `true`. 
```php
'event_before_upload_complete' => true, 
'event_upload_complete'        => true,
```
Так можно делать дополнительную обработку до и после завершения загрузки.

**Мягкий режим**  

В конфигурации плагина выставьте `'lax_mode' => true,`, а на фронтенде вызовите метод `setLaxMode(true)`.  
Пропуск расчёта hash перед загрузкой сокращает общее время. Но с включённой опцией мгновенная загрузка и проверка целостности недоступны.

**Многоязычность**  

Фронтенд определяет язык браузера и подставляет его автоматически; сейчас поддерживаются китайский и английский.
  
**Удобные консольные команды**  

`php webman aetherupload:groups` выводит все группы и автоматически создаёт соответствующие каталоги  
`php webman aetherupload:build` перестраивает в Redis список мгновенной загрузки для файлов ресурсов  
`php webman aetherupload:clean 2` удаляет недействительные временные файлы старше 2 суток  

# Рекомендации по оптимизации
* **(рекомендуется) Настройте ежедневную автоматическую очистку недействительных временных файлов**  
Загрузка может оборваться неожиданно — например, если во время передачи принудительно закрыть страницу или браузер; уже созданная часть файла останется недействительной и займёт много места. Для регулярной очистки можно использовать задания по расписанию в crontab.  
Выполните в Linux команду `crontab -e` и убедитесь, что в файле есть такая строка:  
```php
0 0 * * * php /абсолютный/путь/к/корню/проекта/webman aetherupload:clean 1> /dev/null 2>&1  
```  

* **Настройте ежедневную автоматическую перестройку списка мгновенной загрузки в Redis**  
Неправильная обработка и отдельные крайние случаи могут занести в список мгновенной загрузки грязные данные, что скажется на точности мгновенной загрузки; перестройка списка убирает грязные данные и восстанавливает соответствие реальным файлам ресурсов.  
Выполните в Linux команду `crontab -e` и убедитесь, что в файле есть такая строка:  
```php
0 0 * * * php /абсолютный/путь/к/корню/проекта/webman aetherupload:build 1> /dev/null 2>&1  
```  

* **(необязательно) Включите внутренний редирект nginx — он даёт докачку больших файлов и перемотку видео**  
Ответ webman не реализует HTTP Range: большой файл отдаётся целиком, видео не перемотать, и всё время передачи занят один worker-процесс. Если проект развёрнут под nginx, можно включить в плагине опцию `x_accel_redirect` — файл начнёт отдавать сам nginx, worker освободится сразу, а Range (докачка, перемотка видео) будет поддерживаться.  
Выставьте в конфигурации плагина `'x_accel_redirect' => true,` и добавьте в конфигурацию nginx location для внутреннего префикса, где `alias` указывает на абсолютный путь к корню загрузок проекта (обратите внимание на слеш в конце):  
```nginx
location /internal-aetherupload/ {
    internal;
    alias /абсолютный/путь/к/корню/проекта/storage/app/aetherupload/;
}
```
В этом location обязательно оставьте `internal`, чтобы извне нельзя было обойти приложение и обратиться к файлам ресурсов напрямую; после изменения `root_dir` нужно синхронно поправить и `alias`.  

* **Ускорение чтения и записи временных файлов фрагментов (действует только для PHP)**  
Файловая система tmpfs в Linux позволяет держать временные файлы фрагментов в памяти и читать-писать их быстро: место обменивается на время, скорость операций растёт, но **дополнительно расходуется** часть памяти (примерно размер одного фрагмента).  
В php.ini задайте для каталога временных файлов загрузки `upload_tmp_dir` значение `"/dev/shm"` и перезапустите сервис.  

* **Ускорение чтения и записи временных файлов фрагментов (действует для системного каталога временных файлов)**  
Файловая система tmpfs в Linux позволяет держать временные файлы фрагментов в памяти и читать-писать их быстро: место обменивается на время, скорость операций растёт, но **дополнительно расходуется** часть памяти (примерно размер одного фрагмента).  
Выполните следующие команды:    
`mkdir /dev/shm/tmp`  
`chmod 1777 /dev/shm/tmp`  
`mount --bind /dev/shm/tmp /tmp`

# Безопасность
Перед загрузкой AetherUpload фильтрует расширения файлов по белому и чёрному спискам, а после загрузки проверяет Mime-Type файла. Белый список напрямую ограничивает расширения сохраняемых файлов, чёрный по умолчанию блокирует распространённые расширения исполняемых файлов — так предотвращается загрузка вредоносных файлов; из соображений безопасности белый список оставлять пустым не следует.  

Меры приняты разные, но загрузку вредоносных файлов невозможно предусмотреть полностью, поэтому настройте права на каталог загрузок правильно: у соответствующих программ не должно быть прав на исполнение файлов ресурсов.
